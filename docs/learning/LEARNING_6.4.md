## 2. Architecture changes

```
src/learning/
  answerEngine.js     evaluate() for single / multiple / truefalse / short / numeric;
                      strict number parser, unit tables + conversion, tolerance
  questionBank.js     QUESTION_CHAPTERS; questions/<chapterId>.js loaded on demand
  questions/*.js      one file per chapter, questions keyed by lessonId
  practiceApp.js      Practice Home → Workspace → Feedback → Results → Review (+ practice.css)
  practiceProgress.js learning.practice.{answers,sessions} + resumable session key
  chemMath.js         textbook-rounded atomic masses, molarMass(), 24,79 L/mol
  lessonMeta.js       shared sources/verification wording for lesson files
  catalog.js          FULL_LESSONS set; lessons loaded with import(`./lessons/${id}.js`)
```

- **Lesson schema** (backward compatible): new block `mistakes` ({ wrong, right }[]), callout tone `question` (opening question), `equation.condition` (reaction conditions shown beside the equation), `equation.check: false` for generic or non-chemical text, `worked.table`.
- **Routes:** `#learning/practice` (home), `/session`, `/lesson/<id>`, `/chapter/<id>`, `/topics` (6.2 quiz).
- **Storage:** new data lives under `chemlab-v1-progress → learning.practice` (unknown keys are preserved by `loadProgress`'s merge). The running session is kept in `chemlab-v1-practice-session` so a reload resumes it. No existing key or field changed.

## 3. Quality gates (automated)

`npm run check:learning` = `scripts/test-learning.mjs` + `scripts/test-questions.mjs`.

- Every full lesson: ≥ 6 steps, opening question, worked example, common-mistakes block, ≥ 3 quick checks with explanations, requirements/prerequisites/sources, verification labelled *internal*.
- Every equation block with an arrow is parsed and checked for element and charge balance (`scripts/lib/equation-check.mjs`, half-reactions with electrons supported) unless marked `check: false`.
- Every question: schema, ID form, references, ≥ 20-character explanation; the engine must accept the stored answer and reject a wrong one; numeric questions must carry `verify()` that recomputes the answer within tolerance (≤ 5%) and solution steps.
- Every lesson in a chapter with a question file: ≥ 6 questions and ≥ 3 question types.
- Coverage (`CURRICULUM_COVERAGE.md`) and bank (`QUESTION_BANK.md`) reports are regenerated by `--write` and fail when stale.

## 5. Checkpoint — how to continue

1. `git log --oneline` — each batch is one local commit "ChemLab 6.4 batch N: …".
2. Next batch = next chapter in order (Hóa 10 Chương 2, then 3 … 7, then Hóa 11, Hóa 12). For each chapter:
   - write `src/learning/lessons/<id>.js` per lesson (pattern: `g10-l2.js`), add the IDs to `FULL_LESSONS` in `catalog.js`;
   - write `src/learning/questions/<chapterId>.js` (≥ 6 questions/lesson, ≥ 3 types, `verify()` for numeric), add the chapter to `QUESTION_CHAPTERS` in `questionBank.js`;
   - `node scripts/test-learning.mjs --write && node scripts/test-questions.mjs --write`, then `npm run check`, `npm run build`, `npm run check:browser`;
   - commit with an explicit pathspec (never `git add -A`; the user keeps `AGENTS.md` staged).
3. Already-reviewed lessons are not rewritten.

## 6. Release notes for later

- Bumping the version renames the service-worker cache (`chemlab-<version>-…`), which is what forces clients onto the new assets; do it at release time together with `npm run release:sync`.
- Optional for release: precache lesson and question chunks so the whole curriculum works offline after one online visit.
